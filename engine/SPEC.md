# TurboPDF document tree — specification v1

The **document tree** is the only contract between the SDK (TypeScript) and the engine (Rust).

```
React / Markdown ──(SDK)──▶ document tree (JSON) ──(engine)──▶ PDF + HTML/PNG previews + warnings
```

* **Source of truth:** `crates/turbopdf-tree` (Rust structs, serde). The TypeScript types in `src/tree.ts`
  are *generated* from it (`npm run gen:tree`), so they cannot drift.
* **Strict:** unknown fields, unknown node types, invalid colors/dimensions are rejected at parse time;
  structural problems are reported by `validate()` with a JSON Pointer path and a code.
* **Fixtures:** `engine/fixtures/*.json` are parsed, validated and round-tripped by the Rust tests.

## 1. Conventions

| | |
|---|---|
| Units | **points** (1 pt = 1/72 in). A4 = 595.28 × 841.89 pt. No units in JSON: `12`, not `"12pt"`. |
| Origin | top-left, y grows downward. |
| `Dimension` | `12` (points) · `"auto"` · `"50%"` (of the containing block). |
| `Edges` | `8` (all sides) · `{ "top": 8, "left": 4 }` (missing sides = 0). |
| `Color` | `#rgb` · `#rgba` · `#rrggbb` · `#rrggbbaa` · `"transparent"`. Output is normalized lowercase. |
| Names | node `type` in `snake_case`; style/field names in `camelCase`; enum values as CSS (`"flex-start"`). |
| `id` | optional, unique in the document. Used in warning paths (`id` beats the pointer). |
| `path` | JSON Pointer from the root: `/children/0/children/3/rows/41`. |

## 2. Document

```jsonc
{
  "type": "document",
  "version": 1,                 // must equal TREE_VERSION
  "meta":   { "title", "author", "subject", "keywords", "lang", "creationDate" },
  "defaultStyle": { … },        // root of inheritance
  "fonts":  [ { "family", "weight", "style", "source": { "data": base64 } | { "file": path } } ],
  "bookmarks": true,            // PDF outline from headings 1–3
  "tagged": true,               // structure tree (tagged PDF)
  "pdfua": false,               // PDF/UA-1: needs meta.title + meta.lang; see §4 Accessibility
  "children": [ page, … ]       // ≥ 1 page (section)
}
```

* `meta.creationDate` is **never defaulted to the current time** (determinism). Absent ⇒ no date written.
* `meta.lang` selects hyphenation patterns and the PDF `/Lang`.

## 3. Page (section)

A `page` is a **section**, not a single sheet: its `children` flow onto as many physical pages as needed.

| Field | Default | Notes |
|---|---|---|
| `size` | `"A4"` | `"A3" "A4" "A5" "Letter" "Legal"` or `{ width, height }` in points |
| `orientation` | `portrait` | swaps width/height |
| `margin` | `36` | `Edges`; header/footer live **inside** the margin box |
| `style` | – | `backgroundColor` fills the sheet; text props are inherited by the section |
| `header`, `footer` | – | nodes repeated on **every** physical page of the section |
| `watermark` | – | `{ text, color?="#0000001f", fontSize?, fontWeight?=700, fontFamily?, angle?=45 }` stamped centred on every physical page, drawn last. `angle` is counter-clockwise, in degrees; `fontSize` defaults to fit ¾ of the page diagonal (≤ 200 pt). |
| `children` | – | body nodes |

Layout of a physical page: `margin` → header (height measured) → body (remaining height) → footer.
The body height is therefore `pageHeight − margins − header − footer`.

`{page}` and `{pages}` are substituted in the text of header/footer (and in `page_number.format`).
`{page}` = 1-based index in the **whole document**; `{pages}` = total physical pages. Literal braces: `{{` `}}`.

## 4. Nodes

All nodes accept `id?` and `style?` (except `page_break`). `keepTogether?` exists on `view`, `text`, `heading`, `table`.

| `type` | Fields | Behaviour |
|---|---|---|
| `view` | `children` | Flex container. Default `flexDirection: "column"`. Splittable between children. |
| `text` | `content: string \| Span[]` | Paragraph. Splittable between lines (orphans = widows = 2). `Span = { text, style?: TextStyle, link? }`. `\n` = hard break. |
| `heading` | `level 1..6`, `content`, `keepWithNext?=true` | Like `text` with default sizes `28 22 18 15 13 11` pt, weight 700 (600 for levels 4–6). |
| `image` | `src: {data} \| {file} \| {qr, ecc?, color?, background?}`, `format?`, `alt?`, `fit?=contain`, `link?` | PNG, JPEG, WebP, GIF (first frame), SVG (vector; only document fonts, no external references). `{qr}`: QR code generated by the engine as an SVG (4-module quiet zone, ecc default `M`). **Atomic.** `style.width/height` size the box; default = intrinsic size capped to the content width. |
| `table` | `columns`, `header?`, `rows`, `repeatHeader?=true`, `headerStyle?`, `cellStyle?`, `altRowStyle?`, `keepTogether?` | See §6. |
| `page_break` | – | Ends the current physical page. No-op at the very top of a page. |
| `page_number` | `format?="{page}"`, `target?` | Text with the page number. Allowed anywhere (body too). With `target` (an `id`), `{page}` is the page where that node starts (`?` + `broken_link` if none). |
| `table_of_contents` | `levels?=3`, `entryStyle?` | One line per body heading of level ≤ `levels`: title, then its page number right-aligned; each line links to the heading. |

**Links.** `view.link`, `image.link` and `Span.link` take a URL or `#id`. Clickable areas are written as PDF link
annotations (a box: its fragment on each page; a span: each line box it covers). Only `http:`, `https:`,
`mailto:`, `tel:`, `ftp:` URLs are clickable; `#id` resolves to the first place the node is drawn, otherwise
`broken_link`. Headings without `id` are addressable by their JSON pointer (`#/children/0/children/3`).

**Accessibility (tagged PDF).** Every node maps to a structure element: `heading` → `H1`–`H6` (with its text
as title), `text` → `P`, `image` → `Figure` with `alt` (`alt: ""` → artifact), `table` → `Table` / `TR` /
`TH` (header rows) / `TD`, linked runs and boxes → `Link` with their annotation, `page_number` → `P`. A `view`
without `role` is transparent (its children belong to its parent). `role` on `view` / `text`: `section`, `list`,
`ordered_list`, `list_item`, `list_label`, `list_body`, `blockquote`, `code`, `caption`, `toc`, `toc_item`,
`artifact`. Artifacts: backgrounds and borders, headers / footers, watermark, repeated table headers.
Reading order = document order (absolutely positioned children after their in-flow siblings).
With `pdfua`, an image without `alt` becomes an artifact (`missing_alt` warning), a document without
headings gets one bookmark (its title), and the PDF/UA-1 validator runs while writing: any violation is an
error listing the problems.

### Table details

* `columns[i].width`: points, `%` of the table width, or `auto` (share what remains equally).
* `Row.cells[].colSpan` (default 1). **Σ colSpan must equal `columns.length`** (validated).
* Style precedence for a cell, lowest → highest: `table.cellStyle` → `headerStyle` (header rows) or `altRowStyle` (every 2nd body row) → `row.style` → `cell.style`. Header cells therefore get the padding and borders of `cellStyle` unless `headerStyle` overrides them.
* Cell `children` are normal nodes (so a cell can contain a `view`, an `image`, another `table`).

## 5. Style

All fields optional, CSS-inspired. Unknown keys are an error.

| Group | Fields |
|---|---|
| Flex container | `flexDirection` `flexWrap` `alignItems` `justifyContent` `gap` |
| Flex item | `flexGrow` `flexShrink` `flexBasis` |
| Box | `width` `height` `minWidth` `maxWidth` `minHeight` `maxHeight` `padding` `margin` `border` `borderRadius` `backgroundColor` `position` `top` `right` `bottom` `left` |
| Text *(inherited)* | `fontFamily` `fontSize` `fontWeight (100–900)` `fontStyle` `color` `textAlign` `lineHeight` (multiplier) |

* `border = { width, color, style?: solid|dashed|dotted }` — uniform on all four sides in v1.
* **Inheritance:** only the *Text* group inherits (document `defaultStyle` → page → parents → node). Everything else is per-node, like CSS.
* **Defaults:** `Inter`, 11 pt, 400, `#111111`, `lineHeight 1.4`, `textAlign left`, `fontStyle normal`.
* `display` is always flex; there is no `float` or `overflow` in v1 (overflow is *reported*, never clipped silently).
* `position: "absolute"` with `top` `right` `bottom` `left` (points or `%`): taken out of the flow and placed in
  its parent's box, drawn after its in-flow siblings, on the page where the parent starts. Never split.

## 6. Pagination (the core)

The body of a section is a vertical flow. For each child, with `remaining` = space left on the current physical page:

1. **Measure** the child at the body width (taffy for boxes, parley for text).
2. **Fits** (`height ≤ remaining`) → place it.
3. **Does not fit**:
   1. *Atomic* (`image`, a table **row**, any node with `keepTogether: true`, a `heading` with `keepWithNext` and its next sibling):
      * if it fits on an **empty** page → move it to the next page and emit `moved_to_next_page` (reason `atomic` for images and unsplittable boxes, `keep_together`, or `keep_with_next` when set explicitly). Ordinary text flow is silent: short paragraphs, orphan control, headings kept with the next block by default, a table's header + first row;
      * else (taller than a whole page) → place it at the top of a fresh page, let it overflow, emit `overflow` (`dy` = excess).
   2. *Splittable* (`view`, `text`, `table`) → split:
      * `view`: place the children that fit, continue the rest on the next page (the view's own background/border is cut and restarted — no top/bottom border at the cut);
      * `text`: break between lines, never leaving fewer than 2 lines on either side (if the paragraph has < 4 lines it behaves like `keepTogether`);
      * `table`: rows are placed one by one; **a row is never split**; when a new page starts inside the table, the `header` rows are emitted again first (unless `repeatHeader: false`).
4. A forced `page_break` ends the page regardless of `remaining`.
5. **Horizontal overflow:** a box wider than its container (fixed width, unbreakable word…) is kept as-is and reported as `overflow` with `dx` = excess to the right.

Pagination is **deterministic and greedy** (no look-ahead beyond `keepWithNext`). Header/footer height is measured once per section from page 1 content with `{page}`/`{pages}` replaced by the widest plausible value (`pages` digits), so they cannot change the pagination.

## 7. Fonts

* **Inter** (400, 600, 700, each normal/italic) is embedded in the binary and is the final fallback → identical rendering everywhere.
* `fonts[]` adds faces by `family`/`weight`/`style`. Matching: exact family → nearest weight → style → fallback chain → Inter.
* Only glyphs used are embedded in the PDF (subsets with stable, hash-derived tags).
* A character absent from every font in the chain renders as `.notdef` and emits `missing_glyph` (once per char per path).
* `file` sources are read by the **host** (`ResourceLoader`); the core has no I/O. Without a loader (WebAssembly) a `file` font is a hard error, a `file` image an `image_failed` warning.

## 8. Warnings (returned with the PDF, never thrown)

```jsonc
{ "type": "overflow",           "path", "page", "dx", "dy" }                       // excess in pt (0 when none)
{ "type": "moved_to_next_page", "path", "fromPage", "toPage", "reason" }           // keep_together | keep_with_next | atomic
{ "type": "missing_glyph",      "path", "page", "character", "codepoint", "fontFamily" }
{ "type": "image_failed",       "path", "reason" }
{ "type": "broken_link",        "path", "page", "target" }                         // #target matches no id
{ "type": "missing_alt",        "path", "page" }                                   // pdfua: image without alt
```

## 9. Determinism contract

The same tree must give the **same PDF bytes** on macOS, Linux and WebAssembly. Therefore:

* no clock, no randomness, no environment, no locale; no `HashMap`/`HashSet` iteration (ordered maps only);
* PDF document ID = hash of the layout, not random; object order fixed;
* floats are written with a fixed precision (3 decimals) from `f32` computations performed in a fixed order; no fused multiply-add differences — `-C target-feature=-fma` where needed and no `f32::mul_add`;
* fonts, hyphenation patterns and the default stylesheet are compiled into the binary;
* CI checks the SHA-256 of the output of every fixture on macOS, Linux and wasm.

## 11. Roadmap

1. ✅ **Tree spec** (this document) + `turbopdf-tree` + generated TS types.
2. `turbopdf-fonts` + `turbopdf-text`: embedded Inter, shaping, line breaking, `missing_glyph`.
3. `turbopdf-layout`: style resolution, taffy, pagination (tables, `keepTogether`, header/footer).
4. `turbopdf-pdf` then `turbopdf-raster`.
5. `turbopdf-node` + SDK adapter (HTML/React/Markdown → tree), `turbopdf-wasm`. Chromium removed from the SDK.
6. Benchmarks, determinism CI, then flip the default engine.

## 12. Open questions (decide before step 3)

* **Percent heights** inside an unbounded flow: treat `%` height as `auto` unless the parent has a definite height?
* **`border` per side** (needed for table rules like "bottom border only"): add `borderTop/Right/Bottom/Left` in v1.1?
* **Hyphenation** on by default for `lang`s with patterns, or opt-in (`hyphens: "auto"`)?
* **Images in `cover` mode** clip to the box: needs clip support in both backends (planned in step 4).
